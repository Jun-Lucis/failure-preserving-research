# BIG failure-salvage audit v0.3

**Audit date:** 6 October 2026

This audit extends the initial failure-salvage ledger using the current BIG repository status records. It is conservative: a connection is included only when the later research question is explicitly documented as a response to an earlier limit, failed transfer, invalid protocol, or unstable observable.

## A. High-confidence salvage chains

### A1. B23A/B24 -> B25: reformulating the unification question

B23A limited stronger quantitative-universality claims. B24 then found that the audited BIG sectors did not share one already-established substantive common operator.

The B24-B25 record explicitly states that B25 **changed the unification question**: instead of requiring one native operator across sectors, it asked whether distinct boundary classes could be connected by a typed predictive transfer.

This is a macro-scale example of **QUESTION_REFORMULATION**:

```text
strong universality / common-operator question
  -> not supported / multiple classes indicated
  -> reformulate unification as typed transfer
  -> B25 transfer programme
```

This is not a PASS rescued from a FAIL. It is a new question constructed from a retained limit.

### A3. B25.2 -> B26 -> B26.1 -> B26.2: repairing an invalid transfer domain

B25.2 was `IMPLEMENTATION_INVALID`: the coarse resolution gate failed in some cases and the intended connected/disconnected topology span was not realized.

B26 reopened the transfer question while keeping the B25.1e coefficient frozen. Its first topology-straddling attempt again failed to realize the topology span, so B26.1 temporarily removed action-error evaluation and localized the topology transition itself. B26.2 then froze new, previously unsimulated separations using only that independently localized topology bracket.

The resulting claim-bearing test was valid and produced:

`AB_TOPOLOGY_STRADDLING_FIXED_COEFFICIENT_TRANSFER_FAIL`.

This chain is a strong example of **PROTOCOL_REPAIR** followed by a valid negative result:

```text
invalid transfer test
  -> diagnose domain / topology problem
  -> isolate and localize topology transition
  -> new held-out domain
  -> valid prospective transfer FAIL
```

The scientific gain was not a success verdict. It was a credible geometry-transfer boundary.

https://github.com/Jun-Lucis/BIG-theory/blob/main/docs/research_status_update_B26.md

This is the primary **REPRESENTATIONAL_SALVAGE** case.

## C. Temporal audit status

The provisional temporal question has now been tested in two separate ways.

For broad source-stage reuse prevalence:

```text
B19-B26: 10 / 13 = 76.9%
B27-B40: 12 / 12 = 100%
```

The direction is compatible with more systematic later reuse, but the Fisher exact comparison is not statistically persuasive (two-sided p approximately 0.220), and later documentation is more complete.

For 14 source-result-to-successor-freeze transitions with comparable retained-artifact timestamps:

```text
median latency = 1.20 h
IQR            = 0.49-2.03 h
Spearman rho   = 0.051
p              = 0.864
```

Thus the archive does not support a monotonic acceleration of failure reuse.

- `evidence/failure_reuse_latency_v0_1.csv`
